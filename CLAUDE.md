# CLAUDE.md — Artemis / ACOS operating guide

Read this first, every session. It is the map to where truth lives and the rules for changing the system. It is intentionally **fact-free** — no IPs, ports, schema, or module lists. Those are generated; see below.

## Context precedence (which source wins)

1. **Live repo + live RDS** — always wins on facts. Read the repo directly; verify DB state on the box.
2. **`context/CONTEXT.generated.md`** — runtime/DB snapshot (IP, instance ID, ExecStart, Python, migrations, live schema, next plan days). Machine-generated by `scripts/context_snapshot.sh`, committed. Never hand-edit.
3. **`docs/ARTEMIS_STATE.md`** — authored architecture, roadmap, backlog. Intent only. Any concrete runtime fact here is a bug → it belongs in the snapshot.
4. **This file** — operating rules and disciplines.

If a fact in 3–4 conflicts with 1–2, 1–2 win. Flag the drift; don't propagate it.

## Where things live

- **Facts about the running system** → `context/CONTEXT.generated.md` (generated, committed).
- **Architecture, roadmap, backlog, decisions** → `docs/ARTEMIS_STATE.md` (authored, committed).
- **Email subsystem design** → `docs/EMAIL_MODEL.md` (authoritative; Gmail is source of truth, two-path model, the invariants). Read before any inbox/email work.
- **Secrets** → AWS Secrets Manager via `knowledge/secrets.py` only. **Never on disk**, never in `.env` (only non-secret config like URLs lives in `.env`). `.env`, `credentials.json`, tokens are gitignored.

## Access & deploy

- **Box access:** `ssh rdmis` (SSH tunneled over SSM by instance ID — no public IP dependency, no port-22 exposure). If SSO lapses: `aws sso login --profile rdmis-admin`.
- **The box runs `acos.service`** (`python3.11 -m artemis.main`) via systemd. Restart: `sudo systemctl restart acos`. Logs: `journalctl -u acos -n N --no-pager | cat`.
- **DB queries on the box** need env sourced first: `set -a; [ -f .env ] && . ./.env; set +a`, then `PYTHONPATH="$PWD" /usr/bin/python3.11 ...`. `knowledge.db.execute_query` takes optional params — **use `%s` + params**, never string-interpolate (`execute_query("... where k = %s", (v,))`).
- **Migrate-first deploy:** if a branch adds a migration, apply it to RDS (`run_migrations.py`) and confirm the table exists **before** restarting onto the new code, or the code hits a missing table.
- **ENUM-EXPAND — a migration that adds a value to an enum or CHECK constraint is a breaking change for every consumer that reads it.** Before applying, grep every consumer — box, Lambda, frontend — and add the new value in the same change. **In TypeScript, the fix is the union type, not the switch:** a `never` default only narrows over the values the union declares, so a DB value missing from the union compiles cleanly and throws at runtime. Update the union first; the `never` defaults and `Record<Union, …>` lookups then force every call site. **2026-09-25:** migration 042 added `rest` to `session_type`. Both `blocks.type` switches already had correct `never` defaults, and the plan screen still threw on every rest day, because `rest` was absent from the `Blocks` union. Adding it to the union broke the build at `SESSION_LABELS` immediately.
- **Before a migration that DROPS or RENAMES a column: grep every SELECT, INSERT and UPDATE for that column name — across `artemis/`, `scripts/` AND `api/` (the Lambda) — and report the hits.** A smoke test before the drop proves nothing: it passes *because the column still exists*. **2026-09-20:** migration 039 dropped `health.plan.status`; the Lambda change removed the branch that READ it but left it in `_plan_days`' SELECT list, so `/plan` and `/overview` 500ed (`UndefinedColumn`). Migration applied 17:54:12Z, two requests failed at 17:54:21Z, fix deployed 17:55:52Z — 1 min 40 s of exposure. `/plan` had returned 200 minutes earlier — that check could not have failed.
- **FAIL-CLOSED-RESOLVERS — a resolver that answers "what applies here" must never return a default when it could not read its source.** Silence and absence are different answers, and a fail-open resolver turns an infrastructure error into a plausible wrong value that writes cleanly. **2026-09-26:** `cycle.override_for()` opened its own connection, could not see uncommitted overrides, returned "no override" without raising, and eleven plan rows were rebuilt against the base pattern and committed. The md5 guard could not catch it — that guard proves rows outside the pinned set are untouched, and says nothing about whether the pinned rows were rebuilt correctly. A caller that genuinely wants the default asks for it explicitly (`use_overrides=False`); nothing gets it by accident from a failed read. The one permitted swallow is `dbguard.RealDbInTestError`, which can only be raised while a test is running and means "there is no table here", not "the read failed".
- **An unchanged md5 over untouched rows proves no collateral damage. It does not prove the intended rows were written correctly.** The two guards answer different questions and only one of them was ever being asked. A migration or backfill needs BOTH: the hash over the rows outside the pinned set, **and** an assertion that each rebuilt row matches its expected value. **2026-09-26:** the leave-week write reported an identical hash either side and eleven wrong rows in the same breath — every one of them inside the pinned set, where the hash does not look. Assert the intended values, or re-resolve and diff, before reporting success.
- **PUBLIC-FIXTURES — artemis and gym-display are both public repositories.** Test fixtures must never contain real logged data: no actual session loads, RPE values, bodyweight, or dates tied to real sessions. Use synthetic values outside the real range. Before committing a fixture that looks like health data, cross-check it against `health.session_log` and confirm zero matches. **2026-09-25:** gym-display's history was scanned before going public — 193 blobs matched health-data patterns and all were synthetic, verified against RDS.
- **TYPE-GATE — a passing test suite is not a passing build.** `vitest` does not type-check; `tsc -b` runs only in the build. Before merging anything in gym-display, run the full build command, not the tests. The same asymmetry exists anywhere a check and a deploy use different tools — name the gap rather than assuming one gate covers the other. **2026-09-25:** the gym-display Pages build had been failing since `8a4611e` (#24, 2026-09-23) on two TypeScript errors in *test* files, so neither #24 nor #25 ever reached production. All 517 tests passed the whole time, because vitest never type-checks.
- **On the Mac, run Python as `/opt/homebrew/bin/python3` — never a bare `python3`.** A bare `python3` can resolve to `/usr/bin/python3` (3.9), which cannot import this project at all: every run dies on `ModuleNotFoundError: No module named 'dotenv'` before a single test executes. It bit twice on 2026-09-23. `which -a python3` shows the order, and it can change mid-session. Two places it hides: (1) `python3 -m unittest tests.<file>` silently becomes an import error that looks like a broken test; (2) **`api/deploy.sh` calls bare `python3`** for the column preflight, so deploy it as `PATH=/opt/homebrew/bin:$PATH bash deploy.sh`.
- **Do NOT export `AWS_PROFILE=rdmis-admin` for `api/deploy.sh`.** The ssh config's ProxyCommand (`aws ssm start-session`) takes no `--profile`, so an exported profile with a stale SSO token breaks `ssh rdmis` — and the preflight then fails closed with "could not read acos.schema_migrations", which reads like a box problem and isn't. The default profile is the IAM user `rdmis-crm-admin` and carries the Lambda and SSM access the deploy needs. `aws sso login --profile rdmis-admin` is only for the calls that need admin.
- **DOC-ASSERT — a scripted doc edit must prove it landed.** `str.replace`, `sed` and anchor-based insertions silently no-op when the anchor is absent, and the commit then goes out claiming text it doesn't contain. Any scripted insertion or replacement must (1) assert the anchor occurs **exactly once** before editing, (2) re-read the file after writing and assert the new text is present (and replaced text gone), and (3) exit non-zero on any failure — never print-and-continue. Before committing, check `git diff --stat` against what the commit message claims; a message may only describe what the diff contains. **Three silent no-ops in one week:** `98581be` claimed YOGA-5/YOGA-6/JENI backlog entries it didn't contain (found and fixed in `ab7c0d1`); #141 (`aa47b80`) was meant to add the RPE-SCALE entry and wrote nothing, because its anchor heading didn't exist on that branch — the entry finally landed 2026-09-21; and the first GD-STRENGTH-CUES insertion keyed on a `**YOGA-6` heading that wasn't there, caught only by "nothing to commit".
- **PROPOSE-NOT-IN-MIGRATIONS — a proposed migration must never be written to `migrations/`.** The deploy path runs `run_migrations.py`, so a file placed there is applied on the next deploy whether or not it was approved. Proposed DDL lives in the backlog entry or the PR description until the consumer that needs it is built. **2026-09-25:** CYCLE-OVERRIDE-SOURCE's DDL was proposed into the CALENDAR-1 entry for this reason.
- **The deploy path must run `run_migrations.py`** — merging a migration does NOT apply it (016/017 were merged-but-unapplied for weeks; the migrate-first discipline caught it).

## Disciplines (non-negotiable)

- **Trust the data, not the report.** Verify against actual DB/box state, never tool output or a "done" claim. Every stale fact this project has hit came from trusting a hand-doc over the box.
- **Verify on the live box**, not just test output. A passing local test is not a verified deploy.
- **Propose-then-confirm** for anything touching the system of record or prod. Autonomy ceiling is preview/draft; activation of any standing automation is human-gated (descendant of the Brad Spaits rule — Artemis never autonomously sends external comms).
- **Never invent/deny capabilities.** No confabulated "I've learned that…" — there is no cognition/learning layer yet. Deterministic intent classification must not be overridden by an LLM classifier into a fabricated path.
- **Anchor "today" to the ACTIVE timezone** (default `America/Chicago`). RDS runs UTC; bare `current_date` is a day ahead of Ryan after ~7pm. In Python use `quiet_hours.local_today()` / `local_now()` / `local_tz()`; in SQL use `(now() AT TIME ZONE %s)::date` with `get_active_timezone()` **passed as a parameter** — never interpolate the zone and never hard-code `America/Chicago` outside `config.py`. `tests/test_date_anchoring.py` enforces this. The schedule follows a `set timezone to <place>` override, so a literal would silently pin it to Central while Ryan is away. Elapsed-duration comparisons (24h/12h) are tz-independent — leave them.
- **One system of record.** RDS is authoritative for all operational state. SQLite is fully retired; `artemis.db` is deleted; tests guard against reintroduction. Don't add a parallel store.
- **Gmail is the source of truth for email.** Never build a parallel authoritative inbox state. `acos.email_index` is a mirror; `acos.audit_log` is the action ledger. Verify actions against Gmail before reporting success.
- **Solo-operator scale.** No enterprise patterns (Data Vault 2.0, separate dimensional warehouse, full Iceberg/Glue/Athena). Medallion discipline inside Postgres.

## Branch & PR policy

`feat/*` → PR → `main`. Never push to `main` except the generated snapshot. Branches auto-delete on merge. Two machines push (Mac + EC2) — always `git pull --ff-only` before pushing; never edit the same thing on both.

## Build loop

Changes go through Claude Code: "read the entire codebase / these specific files before writing anything," then exact spec. For migrations/deletions: **coverage-check first** (map each capability to its new home; stop and surface any with no home rather than silently dropping). Return with results; deploy + verify on the box before merge.
