# CLAUDE.md — Artemis / ACOS operating guide

Read this first, every session. It is the map to where truth lives and the rules for changing the system. It is intentionally **fact-free** — no IPs, ports, schema, or module lists. Those are generated; see below.

## Context precedence (which source wins)

1. **Live repo + live RDS** — always wins on facts. Read the repo directly; verify DB state on the box.
2. **`context/CONTEXT.generated.md`** — runtime/DB snapshot (IP, instance ID, ExecStart, Python, migrations, live schema, next plan days). Machine-generated by `scripts/context_snapshot.sh`, committed. Never hand-edit.
3. **`docs/ARTEMIS_STATE.md`** — authored architecture, roadmap, backlog. Intent only. Any concrete runtime fact here is a bug → it belongs in the snapshot.
4. **This file** — operating rules and disciplines.

If a fact in 3–4 conflicts with 1–2, 1–2 win. Flag the drift; don't propagate it.

## Where things live

- **Facts about the running system** → `context/CONTEXT.generated.md` (generated, committed).
- **Architecture, roadmap, backlog, decisions** → `docs/ARTEMIS_STATE.md` (authored, committed).
- **Email subsystem design** → `docs/EMAIL_MODEL.md` (authoritative; Gmail is source of truth, two-path model, the invariants). Read before any inbox/email work.
- **Secrets** → AWS Secrets Manager via `knowledge/secrets.py` only. **Never on disk**, never in `.env` (only non-secret config like URLs lives in `.env`). `.env`, `credentials.json`, tokens are gitignored.

## Session start

Before speccing or building, establish current state (lean — don't exhaust the GitHub 60/hr unauth limit):

- Read `context/CONTEXT.generated.md` (raw fetch — unlimited).
- Default branch + open PRs + branch list — ≤3 API calls.
- Read `PLAYBOOKS.md` for the live playbook inventory.
- Run `compare/main...{branch}` only for branches the session will touch.

Never delete a branch on ahead/behind counts — squash/rebase merges leave branches showing "N ahead" forever. **PR state is the only reliable merged-signal.**

## Access & deploy

- **Box access:** `ssh rdmis` (SSH tunneled over SSM by instance ID — no public IP dependency, no port-22 exposure). If SSO lapses: `aws sso login --profile rdmis-admin`.
- **The box runs `acos.service`** (`python3.11 -m artemis.main`) via systemd. Restart: `sudo systemctl restart acos`. Logs: `journalctl -u acos -n N --no-pager | cat`.
- **DB queries on the box** need env sourced first: `set -a; [ -f .env ] && . ./.env; set +a`, then `PYTHONPATH="$PWD" /usr/bin/python3.11 ...`. `knowledge.db.execute_query` takes optional params — **use `%s` + params**, never string-interpolate (`execute_query("... where k = %s", (v,))`).
- **Migrate-first deploy:** if a branch adds a migration, apply it to RDS (`run_migrations.py`) and confirm the table exists **before** restarting onto the new code, or the code hits a missing table.
- **The deploy path must run `run_migrations.py`** — merging a migration does NOT apply it (016/017 were merged-but-unapplied for weeks; the migrate-first discipline caught it).

## Disciplines (non-negotiable)

- **Trust the data, not the report.** Verify against actual DB/box state, never tool output or a "done" claim. Every stale fact this project has hit came from trusting a hand-doc over the box.
- **Verify on the live box**, not just test output. A passing local test is not a verified deploy.
- **Propose-then-confirm** for anything touching the system of record or prod. Autonomy ceiling is preview/draft; activation of any standing automation is human-gated (descendant of the Brad Spaits rule — Artemis never autonomously sends external comms).
- **Never invent/deny capabilities.** No confabulated "I've learned that…" — there is no cognition/learning layer yet. Deterministic intent classification must not be overridden by an LLM classifier into a fabricated path.
- **CT-anchor "today."** RDS runs UTC; bare `current_date` is a day ahead of Central after ~7pm. For any "today/due-today/overdue" comparison use `(now() at time zone 'America/Chicago')::date`. Elapsed-duration comparisons (24h/12h) are tz-independent — leave them.
- **One system of record.** RDS is authoritative for all operational state. SQLite is fully retired; `artemis.db` is deleted; tests guard against reintroduction. Don't add a parallel store.
- **Gmail is the source of truth for email.** Never build a parallel authoritative inbox state. `acos.email_index` is a mirror; `acos.audit_log` is the action ledger. Verify actions against Gmail before reporting success.
- **Solo-operator scale.** No enterprise patterns (Data Vault 2.0, separate dimensional warehouse, full Iceberg/Glue/Athena). Medallion discipline inside Postgres.

## Branch & PR policy

`feat/*` → PR → `main`. Never push to `main` except the generated snapshot. Branches auto-delete on merge. Two machines push (Mac + EC2) — always `git pull --ff-only` before pushing; never edit the same thing on both.

## Build loop

Changes go through Claude Code: "read the entire codebase / these specific files before writing anything," then exact spec. For migrations/deletions: **coverage-check first** (map each capability to its new home; stop and surface any with no home rather than silently dropping). Return with results; deploy + verify on the box before merge.
